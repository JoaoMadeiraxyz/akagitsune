# Spec Delta

## MODIFIED Requirements

### Requirement: Connecting is joining
The gateway SHALL accept WebSocket upgrades on `GET /ws` without any in-band handshake, and SHALL send the new connection a `{"type":"welcome","id":"<uuid>"}` text frame as its first frame, where `id` is a UUID generated by the gateway for that connection. When authentication is on, the upgrade is accepted only for a request admitted by `connect-authentication`, and no in-band frame ever carries a credential. A new connection SHALL have no subscriptions. That UUID is the only identity the connection has, and it is the `from` value of every text frame and the sender bytes of every binary frame the connection publishes.

Fonte: `src/lib.rs:13` — `app`; `src/ws.rs:53` — `handle_socket`; `src/protocol.rs:14` — `ServerMessage`.
Teste: `tests/gateway.rs:114` — `connection_is_welcomed_with_an_id`; `tests/gateway.rs:164` — `payload_is_relayed_verbatim_to_others`.

#### Scenario: New connection receives its identity
- **WHEN** a client opens a WebSocket to `/ws` and sends nothing
- **THEN** the first frame it receives is a text frame `{"type":"welcome","id":"<uuid>"}` whose `id` parses as a UUID

#### Scenario: Assigned identity is the sender of relayed frames
- **WHEN** a connection welcomed with id `X` publishes a valid text frame to a topic another connection is subscribed to
- **THEN** that subscriber receives it with `"from":"X"`

#### Scenario: Credentials are never an in-band frame
- **WHEN** authentication is on and a client is admitted
- **AND** the client sends a text frame carrying a token
- **THEN** the gateway treats it as any other text frame and does not read it as a credential
